产品需求文档 · PRD v1.1

把"服务器有问题"变成一份能照着做的处置单

本文定义产品的用户、场景、功能需求与验收口径。所有需求均可在当前代码中找到落点； 未落地或部分落地的项，统一记在 风险与未决项。

文档版本PRD v1.1（对应产品 v1.1.0）
状态已实现，生产内网可用（模型端点待切内网）
形态终端交互（TUI）+ 定时巡检；插件形态部署于 dsh / dsh-tui
适用平台麒麟 V10 / 主流 Linux（Windows 仅开发体验）

01背景与问题

生产环境的故障处置，卡点很少在"没有日志"，而在下面三件事：

卡点现在的做法后果
不知道看哪凭经验翻 /var/log，一个个 tail定位时间全花在"找"上，不在"判断"上
看懂了但不敢下结论把报错粘到搜索引擎，翻几页帖子结论依赖个人经验，交接时无法复现
知道要改但不敢改问同事、等审批处置动作没有验收标准，改完不知道算不算修好

同时，通用 AI 助手在生产环境里"不敢用"的原因很具体：它能执行命令。 一次错误的 restart 或误删，代价远超它省下的时间。所以本产品的切入点是把能力切在 "读全、给方案、不动手"这条线上——用可审计的只读能力换敢在生产用的授权。

02目标与非目标

目标（可验证）

  • 运维一句话描述现象，一次交互内拿到带证据的问题清单（不是"建议排查一下"）。
  • 每条问题带处置措施 + 验收标准，人能照着做、做完能自证。
  • 产品的全部能力可审计到每一次工具调用，且审计不可静默篡改。
  • 在无外网、无 python3、dash 为 /bin/sh 的信创环境里装得上、跑得起来。

非目标（明确不做）

  • 不自动修复。没有执行面，是产品定义而非排期问题。
  • 不做通用问答。写代码、翻译、闲聊、时政、投资建议一律拒绝并引回正题。
  • 不做集中式 SOC 平台。它是单机诊断助手，多源事件只做已入库数据的关联。
  • 不替代监控系统。巡检是兜底与日报，不是指标采集与告警平台。
  • 不做模型微调。换模型只换端点，不换行为契约。

03用户与场景

角色场景他真正想要的
值班运维告警响了，登录机器，不知道从哪看一条命令给出"最要紧的是什么 + 先做什么"
系统管理员发版后服务异常，怀疑是变更近 N 小时改了什么、包升级了没、配置被谁动过
安全运营月度自查 / 等保整改基线偏差清单（口令、SSH、sudo、暴露面、SUID）+ 处置建议
交接与审计换班、事后复盘、监管检查谁在什么时候查了什么、拿到什么证据，且这份记录改不了
值班主管每天早上想知道"昨天有没有事"一封日报：扫了哪些日志、有没有问题、最严重的是哪条

04功能需求

优先级：P0 没有它产品不成立 · P1 生产可用必需 · P2 增强项

ID需求优先级验收标准（可测）
FR-01日志地图：列出本机可读日志（路径/大小/mtime/类别）P0 不传参返回全部可读日志；模型不再需要猜路径（提示词与工具描述均要求"先 ls_logs"）
FR-02自动诊断：扫日志 + 匹配 21 类故障 + 给措施与验收P0 单次调用返回 summary / findings / scannedFiles / scannedLines；每条 finding 含级别、计数、样本行号、措施、验收
FR-03精读日志片段（支持 gzip、关键字过滤）P0 传入不在 ls_logs 清单内的路径必须拒绝并说明原因（防任意文件读取）
FR-04资源与进程只读采集：负载/内存/磁盘/inode/D 状态进程、进程 TOP 与详情P0 Linux 上直接读 /proc 与 statfs，不调 df/free/ps；取不到时返回原因而非空值
FR-05网络与服务状态：TCP 状态分布、监听端口、对外暴露标记、unit 启用态P1 读 /proc/net/tcp 与 unit 文件；明确标注"这反映配置为启用，运行态要看 journal"
FR-06变更追溯：近 N 小时配置变更、包变更史、文件 sha256P0 可回答"是不是刚改坏了"；哈希与基线比对可判断内容是否被改（mtime 可伪造）
FR-07安全基线：口令策略 / SSH / sudo / 暴露面 / SUIDP1 返回 findings（含级别、说明、证据、建议）与 checked 检查项清单；纯读
FR-08配置读取：仅白名单路径，默认只给生效行P1 非白名单路径一律拒绝并给提示；支持 grep 与行数上限
FR-09证书检查：有效期与签发信息P2 剩余 30 天内必须提醒；TLS 握手失败可直接归因
FR-10systemd journal 查询（按 unit / 时间 / 级别）P1 唯一允许的子进程；unit 名正则白名单，拒绝 - 开头的参数；macOS 明确报"不适用"
FR-11知识库检索与经验沉淀（五层）P0 kb_lookup 可限定层与条数；kb_note 只能写 memory/，只追加，且必须先征得用户同意
FR-12诊断报告邮件外发P1 收件人必须命中白名单；未配置白名单时一律拒绝；只发正文不发附件
FR-13多源事件关联（Ansible / 天擎 / OneSEC）P2 跨源时间线 + 关联规则（变更后异常 / 同因多发 / 监控盲区），结论带事件 ID 证据
FR-14联网核对报错含义P1 只发查询词，不发日志原文；内网无出口时应失败并降级为"本地推断"而非编造
FR-15定时巡检与日报P1 告警任务仅在命中阈值以上故障时发信；日报每天固定时间；不经过模型；邮件白名单双门槛
FR-16界面收敛与品牌P0 命令表 8 个；启动页只留帮助；参数行只显示 model/effort；不联网查版本；侧栏与启动页为产品自有标识
FR-17审计哈希链P0 每次工具调用一条记录；改任一字段 verify() 必须报断链；跨天续链不误报
FR-18启动自检（8 项）P0 Node 版本、profile 与插件、权限表锁死、沙箱 read-only、界面补丁 + 命令数、审计目录可写、API Key 为阻断级；巡检/linger 为警告级

05非功能需求

维度要求落地方式
访问控制模型侧不存在任何写/执行工具；白名单外调用必须被拒restrict + guard + 沙箱 + 插件禁用（四层）
安全审计工具调用全量留痕，可校验完整性，保留期由运维决定按天分文件 JSONL + sha256 链 + 算法版本
数据完整性审计目录不可被模型写入；文件权限 0600 / 目录 0700数据目录与工具白名单分离，模型无 fs 工具
入侵防范无命令注入面；唯一子进程参数不可控24 个工具零子进程；journalctl 用 execFile + 参数白名单
兼容性麒麟 V10 / glibc ≥ 2.17 / dash / 无 python3 / Node ≥ 18安装与补丁链全 Node 实现；脚本过 dash -n；验收脚本专项检查
可离线内网无外网可完整部署离线包 + install-offline.sh + 平台校验；关掉更新检查
性能单次诊断在"15 文件 × 300 行"量级内秒级返回；日志读取有上限读取行数上限 2000、文件数上限 40、返回条数上限 200
可维护零第三方运行时依赖；单测覆盖核心逻辑dependencies: {}；tests/run.js 断言 79 条

06交互与信息架构

可用命令（8 个，其余已从命令表移除）

命令用途
/help /status看能用什么 / 看当前会话状态
/model切换模型（内网多端点时）
/lang /theme切换语言 / 主题
/exit /quit /q退出

被移除的包括 /context（会摊开系统提示词）、/plugins、/mcp、/hooks、/provider、/update、/workspace 等。

回答必须长成这样

一句话结论：这台机器当前最要紧的问题是什么

问题清单（按严重度排序）
  - 现象：一句话
  - 证据：日志路径 + 行号 + 原文摘录（1–3 行，不贴整段）
  - 根因：事实 / 推断（推断要写依据）/ 资料（来源）
  - 措施：编号步骤，带具体命令
  - 验收：怎么确认修好了

还要什么：信息不足时，明确列出需要用户提供什么

约束：一次最多 5 条问题，其余一句话归纳；扫完没问题就直接说"没发现已知故障模式"，并说明扫了哪些、哪些维度没覆盖。

07度量指标

指标口径目标
定位时长从提问到拿到"最要紧那条"的时间较人工翻日志明显下降（以值班记录对比）
结论可执行率给出的措施中，人能直接照做的比例≥ 90%（"建议排查一下"不计入）
证据完整率带路径+行号或事件 ID 的结论占比100%（纪律层硬要求）
规则误报率被人工判定为误报的 finding 占比持续跟踪，按规则逐条调阈值
审计链完整率verify() 通过的天数占比100%
巡检到达率定时任务实际执行次数 / 应执行次数≥ 99%（受 linger 影响，需自检兜底）

08发布与验收

发布前必须通过 tools/acceptance.sh 的六类检查，全部通过才算可交付：

类别检查内容
运行时依赖Node ≥ 18；安装链路不依赖 python3；tar / gzip 可用
Shell 兼容全部脚本过 dash 语法检查；无 bash 专有语法；无 BSD 专属 sed -i ''
命名残留无历史项目名残留
文件权限install.sh 与 bin/ 下脚本具执行位
单元测试全部断言通过
安装包可解压、目录完整、bin/soc 保留执行位、无 node_modules 与备份文件

上线前的人工确认项：soc --check 八项全绿、真实故障复现一次、审计 verify() 通过、定时任务收到一次真实邮件。

09风险与未决项

项状态影响与应对
内网模型端点未定高当前用云端 key 联调，交付前必须切内网并全量复测；否则合规不成立
天擎 / OneSEC 适配器无真实样本中适配器标 verified: false；接入前需用真实导出重新校准字段映射
10 万行日志压测未做中当前按行数上限截断；大日志场景的性能与准确率均未验证
数据库只读连接器未接真实驱动中SELECT-only 拦截已就位，但未连真库验证
框架内建 71 个 slash 命令低属 UI 内建，插件层关不掉；有风险的三个入口对应插件已被禁用
单测夹具缺失中7 条 Ansible 用例依赖未随包发布的 dsh-ansible-logs/fixtures，交付包内跑不全绿，见 技术债
